GEURTS PERFORMANCE PREFECT 1.38.0 — WINDOWS x64

FILE COMPRESSION
Automatic compression is off by default. Choose one drive, then use Automatic
compression to set sliders for compressing at high fullness and decompressing
at low fullness (defaults 85% and 70%). Keep at least a five-point gap. Select
threshold-only new files or always-new files; always-new files created after
enabling are kept compressed while the thresholds manage older files. Enable
and confirm, then use Apply for changes. Runs while Prefect is open/in the tray.
The first check is in one minute. Stop and disable keeps completed changes.

Scan and compress drive checks each file and compresses it immediately if eligible,
then moves on. Select a drive and confirm once before starting. No full preview
is needed. Windows and protected files are skipped. Stop keeps completed changes
and finishes the current file. Use Preview entire drive to review files first.

Settings > File compression saves disk space with lossless NTFS compression.
Choose files or a data folder, preview sizes and states, then confirm Compress
or Decompress. Files stay readable and editable normally; no extraction is needed.
Nothing runs automatically. Only existing previewed files change; folder defaults
stay unchanged. Choose entire drive accepts a local NTFS drive root such as C:\.
Preview entire drive scans eligible files while skipping Windows, standard app
and settings folders, all users' AppData, boot/recovery paths and protected files.
Totals and confirmation include every eligible previewed file; the list displays
the first 500. Drive preview has no file-count cutoff. Stop waits for
the current file and keeps completed changes. Decompression needs free space.
Savings and performance vary, especially for already compressed media/archives.

DISK ANALYSER PROTOTYPE
Settings > Disk analyser embeds a themed WinDirStat 2.9.3 build. Each scan reads
the current Settings colours and font, with coordinated graph colours. Native
icons/control shapes remain WinDirStat's; Windows high contrast takes precedence.
Choose a drive or folder and
click Analyse to start. Browse the file tree, largest files and treemap inside
Prefect. Close analyser before Done, restarting or updating Prefect. App exit
automatically stops its private analyser and dialogs. Completed changes remain;
interrupted operations may be incomplete. Review deletion prompts carefully.
Protected-folder scans need Prefect opened as administrator first. Each session
uses temporary portable preferences. Licence and source opens the bundled offline
GPL licence and upstream source archive. No separate installation is needed.
Mixed-DPI monitor transitions and WinDirStat's own elevated relaunch are not
validated; elevated relaunch may open a separate window. Installation is manual.

Open Geurts Performance Prefect\GeurtsPerformancePrefect.exe, then click Settings.
The existing HardwareOverlay.exe launcher also opens the updated application.

SECURITY
Settings > Security > BitLocker drive decryption can turn off BitLocker and
decrypt one selected drive and its contents. Run Prefect as administrator, load
the drive list, choose the drive explicitly and confirm before starting. Normal
sessions offer an administrator restart that reopens Security without decrypting.
Keep a current backup and recovery key available until Windows finishes. The
drive loses BitLocker protection; files stay in place. Closing Prefect after the
request is accepted does not stop Windows' background decryption. Keep the drive
connected and power available. Refresh for conversion status and percent still
encrypted; active decryption refreshes every 15 seconds while the tab is visible.
Locked drives must first be unlocked in Windows. Paused decryption can be resumed.
Turning encryption back on requires a separate setup in Windows. Separate EFS
file encryption is not removed. No decryption happens on startup or from opening
Settings. Organization policy and auto-unlock dependencies are respected.

Settings > Security > Windows Firewall offers Disable Windows Firewall for all
three network profiles: Domain, Private and Public. Confirm before applying;
administrator approval may be needed. This reduces protection against unwanted
network access, including on public Wi-Fi. No restart is normally needed.
Restore / enable Windows Firewall restores each profile's previous setting, or
enables all three without a backup. Rules and the firewall service are preserved.
Status shows local settings; organization policies may override them. Nothing
changes automatically when Prefect starts or when you open the Security tab.

Settings > Security contains Start as administrator for Prefect and a separate
Windows-wide Run all apps as administrator without prompts action. The latter
disables User Account Control (UAC) after confirmation and administrator approval.
Restart Windows yourself to apply it. Administrator accounts can then launch apps
with full permissions without UAC prompts; standard accounts remain limited.
This reduces protection against unwanted system changes. Restore / enable UAC
protection restores the previous setting, or enables UAC if no backup is saved.
Restart Windows after restoring too. Nothing changes merely by opening the tab.

SETTINGS AND CONSOLE
Settings > Console > Disk fragmentation offers Analyze and Optimize drive.
Choose a local drive and Analyze drive to review fragmentation without changing
it. Optimize drive asks for confirmation and lets Windows choose the appropriate
operation for the media type, including SSDs. Administrator access is required.
Progress and Windows' report appear in the console. Analysis can be stopped;
Done waits for optimization; app exit stops its command automatically. No operation starts
automatically, restarts Windows or changes scheduled optimization settings.

Settings now opens wider and taller, capped to fit your screen.
The Console tab embeds disk checks, system integrity scans and Windows image
checks/repairs. Use Restart as administrator there when required; Windows asks
for approval and Prefect reopens Console. Choosing a mode never starts a command.
Output survives switching tabs and minimising. Stop cancels read-only checks;
closing waits for them to stop. Repairs retain their confirmation and prompt
controls. App exit shows a warning, stops owned commands and exits automatically;
interrupted repairs may be incomplete. Done waits until repairs finish. Restart/update
installation waits for active commands. No check or repair runs automatically.

CLOSE BORING APPLICATIONS
Settings > Performance > Close Boring Applications loads installed desktop apps.
Search and select apps, then use the close button to terminate their processes
with one click. Save your work first: forced closure can lose unsaved changes.
Selections save automatically. Nothing closes automatically or on startup.
Refresh reloads the installed list. Add executable supports apps with no detected
executable, portable apps and Store apps. Show selected applications only filters
your saved list. Hover over an entry to review its saved executable paths.
After an app moves or changes its versioned folder, deselect and reselect it.
Windows, critical processes, Prefect and other sign-in sessions are protected.
Failures are reported; some apps may restart themselves. No elevation is requested.

POWER OPTIONS
Settings > Performance offers Performance Mode Only, and Performance Mode
Plugged and Ultra Battery Saving Unplugged. Enable Apply selected power preset
on app startup to apply it on future launches (off by default), or choose Apply
preset now. Administrator approval may be needed. The battery CPU performance
limit defaults to 50% and can be increased to 100%; it is not a hard cap on
Task Manager CPU usage. Battery saving enables core parking, dims at 30 seconds,
turns the screen off at 1 minute, sleeps at 2 minutes, and hibernates at 5 minutes
where available. Plugged-in values use full performance and no automatic sleep
or screen-off. Performance Mode Only uses these values for battery too.
Restore previous power plan switches back and disables startup application.
Turning just the startup toggle off leaves the current Windows plan active.
Windows switches AC/battery values automatically even after Prefect exits.
Unavailable or locked settings and values outside Windows' allowed range are
skipped individually and listed in the status, including separate AC/battery
limitations. Supported values are verified before and after activation. If no
values can be written, the original plan is preserved. A Balanced-derived
fallback is tried when Windows rejects the original plan as unsupported; Restore
still returns to the original. Helper errors appear directly in the main status.
Hardware/vendor controls and Windows policy
can limit their effect. Critical battery protection is retained.

START WITH WINDOWS
Settings > Startup > Start with Windows opens the overlay automatically when
you sign in to your Windows account. Off by default; changes save immediately
without administrator approval. Turn it off to remove this app's startup entry.
Keep the app in the same folder. If you move it, turn the option off and on from
the new location. Updates in the same folder keep the startup entry. Windows
Settings > Apps > Startup must also allow the app. Existing overlay preferences
apply; Downloads auto-wipe also runs if you enabled it. If already running,
a Windows startup launch exits quietly.

APPLICATION UPDATES
Settings > Application Updates > Check for updates checks the public repository:
  https://github.com/Geurtsy/Geurts-Performance-Prefect
When a newer release is available, Install update and restart downloads and
verifies it, saves preferences, closes the app, installs and reopens Settings.
Preferences stay in the existing HardwareOverlay settings folder. Backups and
update results are under its Updates subfolder. A protected application folder
may require administrator approval. Versions before 1.5.0 need a manual upgrade
once to gain the updater. Normal monitoring continues to work offline.

DOWNLOADS CLEANUP
Settings > Downloads Cleanup > Wipe Downloads now permanently deletes files
and subfolders after you confirm the displayed folder. The Downloads folder
itself is kept. Deleted items do not go to the Recycle Bin.
Auto-wipe Downloads on app startup is off by default. Enable and confirm it to
wipe once per app launch, starting with the next launch, without another prompt.
This includes app restarts after updates or administrator elevation. Disable it
to stop future startup cleanup. The manual button works with auto-wipe off.
The current Windows Downloads location is used. Locked, read-only, inaccessible
and linked items are skipped; Settings shows the result. Run the application
outside Downloads: cleanup refuses folders containing the running app or its
settings, protected Windows folders, drive roots and folder links/junctions.

TOP APPLICATIONS
CPU, GPU, RAM and each physical drive show the application with the highest
average usage over the last 60 seconds. Settings > Overlay > Top Applications changes the
averaging window from 5 seconds to 10 minutes and saves your preference.
Processes with the same executable name are combined. CPU and GPU show average
usage, RAM shows average physical working set, and drives show average read/write
throughput. While starting, averages use the samples collected so far.
Per-drive application tracking needs Settings > Restart as administrator.
GPU attribution follows your selected graphics card and needs supported counters.

HARD DRIVE USAGE
Settings > Overlay > Hard Drive Usage lists each detected physical drive, including SSDs.
Tick a drive to show its activity (%) in the overlay; untick it to hide it.
Each choice saves between launches. New drives appear automatically.
Activity is the percentage of time the drive is busy reading or writing.
Drive labels include disk numbers and volume letters; details show the model.
The first sample, disconnected drives and unavailable counters show no reading.
Drive discovery refreshes every 10 seconds. Drive activity uses Windows counters
and does not require the PawnIO driver. The overlay scrolls when needed.

REMOVE CORE PARKING
Settings > Performance > Remove Core Parking applies:
  powercfg /setacvalueindex SCHEME_CURRENT SUB_PROCESSOR CPMINCORES 100
  powercfg /setactive SCHEME_CURRENT

The app captures the active plan's GUID so both commands target the same plan.
Approve the Windows administrator prompt when you turn the setting on or off.
The checkbox reflects the actual AC value on the active plan. Refresh power plan
rechecks it after another app switches plans. Opening the app or Settings does
not change Windows power settings.

Turning the setting off restores the previous AC percentage saved for that
plan. Restoration survives application restarts. If the plan was already at
100% before this app changed it, it shows enabled without offering an invented
restore value. Battery power and other processor settings are unchanged.
Keeping cores unparked may increase power consumption and heat.

OVERLAY
Auto-avoid is available in Settings > Overlay and in the tray's right-click menu.
Enable it to anchor the overlay to the nearest corner of its current monitor.
When the cursor enters it, the overlay moves to another corner clear of the
pointer and remains anchored there. It uses top left, top right, bottom left,
and bottom right within the monitor's working area, leaving room for the taskbar.
Changes to overlay size/readings keep the selected corner anchored.
The toggle and selected corner save between launches; the toggle defaults off.
When Auto-avoid is on, use the tray for Settings or to disable it before dragging.

Click the — button in the header to minimise the application.
Settings > Overlay > Minimise to tray is enabled by default. It hides the overlay
and any open Settings window in the notification area. Double-click the tray
icon, or right-click it and choose Restore, to bring them back. The tray's
Settings command also restores the application. Disable Minimise to tray to
use normal taskbar minimising. The preference saves between launches.

The six system readings and each drive have independent switches. Always on top, opacity, size,
refresh interval and sensor choices apply immediately. Drag the application
header to move the overlay. Right-click or use the tray icon for Settings/Exit.
F2 opens Settings. For games, use windowed or borderless mode.

Existing preferences are preserved in:
  %LOCALAPPDATA%\HardwareOverlay\settings.json
This legacy folder is retained for compatibility with the previous release.

FAN FULL-ON MODE
Settings > Fan control > Full-On Mode requests maximum output on every supported
writable fan channel, including channels detected later, regardless of temperature.
It stays active while Settings is closed or the overlay is minimised. Turn it off
or choose Restore all to return session-controlled fans to hardware automatic.
Normal exit also restores hardware control. Full-On Mode starts off each launch.
Some hardware exposes RPM readings without writable controls; review the status
for unsupported channels or failures. Automated tests do not change physical fans.

TEMPERATURE ACCESS
CPU/motherboard temperatures may need Settings > Restart as administrator and
the PawnIO driver. On first launch, the bundled official PawnIO installer runs when the driver is missing; approve the Windows administrator prompt.
Unsupported sensors show unavailable. If installation is declined or fails, the app tries again next launch.

REQUIREMENTS
Windows x64 with the .NET 10 Desktop Runtime. Dependencies and licences remain
bundled. The app works offline. See Source\Build.txt for build instructions.

VALIDATION
Release build and automated checks cover existing overlay behavior, branding,
native minimising/restoration, tray/taskbar switching, saved minimise preference,
settings-window restoration and window-position preservation,
Auto-avoid menu synchronisation, native placement at all four corners, mouse-enter
handling with simulated pointer coordinates, resizing and saved corner selection,
per-drive activity, saved visibility, reconnection with changed disk numbers/letters,
core-parking apply/restore, saved restoration values, permission failures,
activation failure rollback, changed plans and mismatched readback. Performance
tests use a simulated backend and do not modify the real power plan. Administrator
approval and the real system-changing operation require testing via the setting.
